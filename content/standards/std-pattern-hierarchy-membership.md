## Intent

Every row in the universe must resolve to a **populated parent node** in a related hierarchy
table, correlated on the universe row's full key. Detected by two regexes that must BOTH match
the rule name, case-insensitive:

| # | Regex (source form) | Signal |
|---|---|---|
| 1 | `\bcustomer\b[\s\S]*\bhierarch\w*\b` | a customer + hierarchy phrase pair |
| 2 | `\bparent\b[\s\S]*\bcustomer\b` OR `\bcustomer\b[\s\S]*\bparent\b` | a parent-customer phrase in either order |

The AND semantics matter: "customer hierarchy" alone does not fire the pattern, and neither does
"parent customer" alone. Both signals must be present in the same rule name.

## Slots

| Slot | Source | Editable |
|---|---|---|
| `universe_table` | `domain_def.salesTable` (customer domain) — fixed `KNVV` | no |
| `hier_table` | `engine.get_join('KNVV', 'KNVH')` target — the KB join, not a hardcode | yes |
| `correlation_keys` | the same join's `key`, parsed into field pairs | yes |
| `parent_field` | fixed `HKUNNR` — `KNVH`'s higher-level/parent-customer column, verified in the SAP ECC baseline | no |
| `org_label` | the org-unit phrase detected in the rule text ("Sales Organization" etc.); documentary only | yes |

## Skeleton essence

A correlated `NOT EXISTS` against the hierarchy table:

- correlate on **every** key pair from the KB join, plus `zSourceSystemID` (patterns never
  correlate across source systems);
- require the parent field to be **non-blank**, not merely present — `COALESCE(parent, '') <> ''`;
- error when the subquery finds nothing: `WHEN NOT EXISTS (…) THEN 1 ELSE 0`.

Every table reference is working_db-qualified through `_qtable`; the explanatory header is a
`/* … */` block comment so the SELECT-list comma handling stays correct.

## Worked example

**Rule:** *"Every active Sold-To customer must be assigned to a valid parent customer hierarchy
within the same Sales Organization"*

**Slots resolved:** `universe_table=KNVV`, `hier_table=KNVH`,
`correlation_pairs=[(KUNNR,KUNNR), (VKORG,VKORG), (VTWEG,VTWEG), (SPART,SPART)]` (from the
`KNVV → KNVH` join key in `knowledge/erp/sap_ecc/joins.json`), `parent_field=HKUNNR`.

```sql
/* Pattern: hierarchy_membership — every KNVV row must resolve to a
   populated parent-customer node in KNVH (HKUNNR) for the same KUNNR, VKORG, VTWEG, SPART. */
    CASE
        WHEN NOT EXISTS (
            SELECT 1 FROM [WRKDQ].[dbo].[KNVH] AS KNVH
            WHERE KNVH.KUNNR = KNVV.KUNNR
              AND KNVH.VKORG = KNVV.VKORG
              AND KNVH.VTWEG = KNVV.VTWEG
              AND KNVH.SPART = KNVV.SPART
              AND KNVH.zSourceSystemID = KNVV.zSourceSystemID
              AND COALESCE(KNVH.HKUNNR, '') <> ''
        )
        THEN 1 ELSE 0
    END AS [zIsErrorFlag]
```

That output is generated by running `detect_pattern` → `fill_slots` → `build_pattern_logic`
against the rule text with working_db `WRKDQ` — not hand-transcribed.

## Templates the pattern narrates with

- **Description:** "Every active `{universe_label}` must resolve to a valid, populated
  parent-customer node in `{hier_table}` for the same `{correlation_desc}` — enforced via a
  correlated NOT EXISTS subquery."
- **Specification:** "zIsErrorFlag = 1 when no `{hier_table}` row exists for this
  `{universe_table}` record's `{correlation_desc}` with a non-blank parent-customer field
  (`{parent_field}`)."

## Notes and boundaries

- The universe is the **sales-area view** `KNVV`, not the central master — hierarchy assignment
  is a sales-area fact, so the row granularity has to match.
- `parent_field` is fixed rather than KB-resolved: `HKUNNR` is `KNVH`'s higher-level/parent-customer
  column, and it is baseline-verified before the pattern trusts it.
- The org-unit phrase ("within the same Sales Organization") is documentary. The actual
  correlation comes from the KB join, which already includes `VKORG` — the pattern never
  re-derives the correlation from prose.
